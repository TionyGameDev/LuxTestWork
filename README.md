## 🎯 Результат

Отзывы → **темы и тон** → **сводка в Telegram**: сколько отзывов по каждой теме, на что жалуются чаще всего (с цитатами) и что изменилось к прошлой неделе.

| На лёгких отзывах | На трудных отзывах (сарказм, отрицание, английский) |
|:---:|:---:|
| правила по словам **90–93%**, LLM **95–96%** | правила по словам **22%**, LLM **97%** |

> **Главная мысль.** Простой поиск по словам справляется с очевидным, но не понимает смысл («совсем не шумит» он принимает за жалобу). Поэтому разметку делает LLM, а **числа и цитаты считает обычный код**: модель не может выдумать цифру.

📹 **Скринкаст до 3 минут:** от загрузки отзывов до сводки в Telegram <!-- сюда вставить ссылку на видео -->

## 🗺 Схема решения

![Схема решения](docs/architecture.svg)

| Вопрос из задания | Ответ |
|---|---|
| **Откуда отзывы** | CSV с колонками `DATE, SKU, RATING, TEXT`; API маркетплейса можно подключить вместо CSV |
| **Как попадают на разбор** | загрузчик проверяет строки (дата, оценка 1–5, текст), битые пропускает с причиной, на разметку идут пачками по 10 |
| **Где хранится результат** | кэш разметки в `data/cache/` (с версией промпта и модели); эталон и результаты проверок в `data/` и `results/` |
| **Как сводка доходит до команды** | Telegram-бот; запуск по расписанию в GitHub Actions (понедельник, 06:00 UTC) |

## 🚀 Запуск

Нужен только Python 3.10+. Внешних библиотек нет.

| Режим | Что нужно | Команда |
|---|---|---|
| 🆓 **Без ключей** (разметка по словам, печать в консоль) | ничего | `python -m src --provider keywords` |
| 🤖 **Anthropic** | `ANTHROPIC_API_KEY` | `python -m src --provider llm` |
| 🌐 **OpenRouter и другие OpenAI-совместимые** (есть бесплатные модели) | `LLM_API_KEY` | `python -m src --provider openai` |
| 🏠 **Локальная модель (Ollama)** | Ollama + модель | `python -m src --provider openai` |
| 📨 **С отправкой в Telegram** | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | добавьте `--send` |

Ключи хранятся в файле `.env` (в git он не попадает). Образец: [`.env.example`](.env.example).

**Полный запуск: разметка моделью и отправка сводки в Telegram:**

```bash
python -m src --provider openai --send
```

> На Windows вместо `python` может понадобиться `py`: `py -m src --provider openai --send`. Если Telegram не настроен, уберите `--send`: сводка просто напечатается в консоли.


Если бесплатная модель перегружена (ответ 429), программа сама ждёт и повторяет запрос.


</details>

**Другие команды:**

```bash
python -m src.evaluate --provider openai --split hard   # проверка точности по эталону
python -m unittest discover -s tests -t .               # тесты
```

Свои отзывы: CSV с колонками `DATE, SKU, RATING, TEXT` (дата `ДД.ММ.ГГГГ`), путь через `--csv`. Неделя это 7 дней, заканчивающихся в последний день данных (или в `--end`).

## ⚙️ Как это устроено

| Шаг | Файл | Что делает |
|---|---|---|
| 1. Загрузка | [`src/load.py`](src/load.py) | читает CSV, пропускает битые строки с причиной, считает id отзыва |
| 2. Разметка | [`src/classify.py`](src/classify.py), [`prompts/classify.md`](prompts/classify.md) | LLM ставит темы и тон, ответы кэшируются |
| 3. Проверка ответа | [`src/classify.py`](src/classify.py) | проверка формата; при ошибке повтор только по проблемным отзывам, модели передаётся текст ошибки |
| 4. Подсчёт | [`src/aggregate.py`](src/aggregate.py) | счётчики, топ жалоб, сравнение недель |
| 5. Сводка | [`src/report.py`](src/report.py) | текст для Telegram, делится на сообщения по лимиту |
| 6. Отправка | [`src/telegram.py`](src/telegram.py) | повторы при сбоях, токен в ошибки не попадает |
| Расписание | [`.github/workflows/`](.github/workflows/weekly-digest.yml) | по понедельникам запускает тесты, затем сводку |

**Принципы**

- 🧮 **Модель только размечает. Числа и цитаты считает код.** Цитата в сводке это дословный текст отзыва, который выбирает код, а не модель.
- 📋 **Темы заданы одним списком** в [`src/config.py`](src/config.py): промпт, оценка и сводка берут их оттуда, поэтому недели сравнимы.
- 🚫 **Тихой подмены нет.** Если LLM недоступна, скрипт сообщает об этом и не переключается на ключевые слова. Неразобранные отзывы попадают в сводку как «не разобрано».
- 📉 **Тренд только от 3 жалоб.** «1 → 2» не называем ростом.
- 🧐 **Флаг «оценка и текст расходятся»** показывает отзывы, где звёзды и смысл не совпадают (часто это сарказм).

## 📊 Проверка точности

Эталон [`data/gold.csv`](data/gold.csv) (правильные темы и тон для каждого отзыва) разделён на три группы:

| Группа | Отзывов | Для чего |
|---|:---:|---|
| **dev** | 30 | настройка промпта |
| **test** | 15 | финальная проверка, до неё не трогали |
| **hard** | 12 | трудные случаи: отрицание, сарказм, английский, неявные жалобы |

**F1 по меткам «тема + тон»** (100% значит полное совпадение с эталоном):

| Вариант | dev (30) | test (15) | hard (12) |
|---|:---:|:---:|:---:|
| Ключевые слова | 90% | 93% | **22%** |
| LLM (`nvidia/nemotron-3-ultra-550b-a55b:free`) | 96% | 95% | **97%** |

**Доля верного тона среди угаданных тем:**

| Вариант | dev | test | hard |
|---|:---:|:---:|:---:|
| Ключевые слова | 95% | 100% | 50% |
| LLM | 98% | 95% | 100% |

Полные выводы с расхождениями лежат в [`results/`](results). Промпт после первого прогона не менялся.

```bash
python -m src.evaluate --provider keywords --split all
python -m src.evaluate --provider openai --split dev    # или --provider llm для Anthropic
python -m src.evaluate --provider openai --split test
python -m src.evaluate --provider openai --split hard
```

## 🧠 Разбор

### Что показывают цифры

На обычных отзывах простые правила по ключевым словам почти не уступают LLM. Разница появляется на трудных отзывах: там правила дают 22%, а модель 97%. Правила ищут слова и не понимают смысл: «совсем не шумит» они считают жалобой на шум, а отзывы без знакомых слов («мотор как новый спустя полгода») относят к «другому».
Модель читает смысл, поэтому справляется и с отрицанием, и с сарказмом, и с английским. Для реальных отзывов, которые обычно разнообразнее и "грязнее" моих, это важный аргумент в пользу LLM.

### Где модель ошибается

Стоит учесть, что LLM тоже может ошибаться: 5 расхождений на 57 отзывов.

- «Кофе вкусный, доставка 6 дней»: модель поставила нейтральный тон. Это неявная жалоба без эмоциональных слов. Что считать недостатком, зависит от ожиданий бизнеса (обещанный срок, норма по категории), и модель этого знать не может.
- «Начал гудеть через месяц»: модель добавила тему «надёжность». Граница между «шумит» и «ломается» размыта, и в промпте её нужно прописать явнее.
- «Приехала в коробке, которую явно роняли, но внутри всё цело»: модель добавила «надёжность: хвалят». Здесь, скорее всего, неточен эталон, а не модель: «внутри всё цело» действительно говорит о состоянии самого товара, и я такую тему в эталоне не отметил. Но случай показывает пробел в промпте: он не объясняет, где проходит граница между «упаковкой» (коробка) и «надёжностью» (сам товар). Это нужно прописать явно и решить с маркетингом, нужна ли такая тема в сводке.

### Ограничения

Выборка маленькая (57 отзывов), отзывы и эталон составлены мной (с помощью ИИ), а не взяты из реального магазина. Поэтому цифры показывают тенденцию, а не точность в продакшене.
Отдельный набор hard я не использовал при написании промпта, но писал его уже после того, как увидел типичные ошибки на обычных отзывах, так что он не полностью независим.

### Что я бы сделал дальше

- Проверить модель на реальных отзывах и собрать эталон вручную с двумя разметчиками.
- Для неявных жалоб ввести правило (например, срок доставки больше N дней), согласованное с маркетингом.
- Спорные отзывы (где модель не уверена) отправлять на ручную проверку.

### Вопросы маркетингу до старта

1. Какие маркетплейсы и сколько отзывов в неделю? От этого зависит стоимость и способ получения данных.
2. Кто читает сводку и как часто? Один чат или несколько?
3. Какие темы реально важны?
4. Что считать срочным сигналом? Нужны ли мгновенные оповещения, а не раз в неделю?
5. Сколько дней доставки считать жалобой?
6. Что делать с отзывами без текста, с рекламой и с отзывами конкурентов?

### Что я бы сделал в продакшене

- **Источник.** Вместо CSV подключил бы API маркетплейса (например Wildberries или Ozon) и забирал бы только новые отзывы.
- **Хранение.** Сейчас разметка не сохраняется между запусками в GitHub Actions, и каждая неделя размечается заново. В продакшене хранил бы отзывы и разметку в базе данных вместе с версией промпта и модели, чтобы сравнивать недели без повторных запросов и пересчитывать прошлое при смене промпта.
- **Качество.** Собрал бы эталон из реальных отзывов, лучше с двумя разметчиками, и каждую неделю проверял бы выборку вручную (например 30 случайных отзывов), следя, не падает ли точность. Отзывы, где модель сомневается, отправлял бы на ручную проверку.
- **Срочные сигналы.** Не ждал бы понедельника для критичных тем (перегрев, безопасность) или резкого роста жалоб по одному товару: присылал бы оповещение сразу. Порог согласовал бы с маркетингом.

## ⚠️ Честные ограничения

- Отзывы в `data/reviews.csv` синтетические: их написал ИИ по образцу из задания, затем я оставил в них неоднозначные случаи (сарказм, несколько тем, «ок»).
- Эталон `data/gold.csv` сначала составил ИИ, поэтому в спорных случаях метки могут быть неточными (см. «Где модель ошибается»).
- Базовые правила в `src/keywords.py` писались с оглядкой на первые 45 отзывов, поэтому их точность на них оптимистична. Это ориентир, а не честная оценка.
- В GitHub Actions кэш разметки не сохраняется между запусками, так что каждая неделя размечается заново. Для данных этого размера это дёшево.
- Реальный API маркетплейса не подключён, источник пока CSV.
- Результаты в таблице получены через `--provider openai` (OpenRouter, модель Nemotron). Режим `--provider llm` (Anthropic) в этих прогонах не использовался.
